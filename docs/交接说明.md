## 1. 项目背景

安卓 App「休息豆芽」，包名 `io.iftech.healthreminder`。最初是本地健康提醒工具（喝水 / 护眼 / 走动，到点全屏霸屏提醒 + 记录 + 日历统计）。现在扩展成多个模块：

| 模块 | module 值 | 说明 | 霸屏页 |
|---|---|---|---|
| 身体 | `body` | 原有健康提醒 | `ReminderActivity` |
| 任务 | `task` | 每日任务清单、打卡、子任务 | `TaskReminderActivity` |
| 任务总览 | `task_all` | 时段内每 N 分钟轮询全部任务 | `TaskOverviewReminderActivity` |
| 子任务 | `subtask` | 挂在任务下，deckId 存 `p<父规则id>` | —（在任务页内勾选） |
| 卡片 | `card` | JSON 导入 / 手动新建的卡片集 | `CardReminderActivity` |
| 答题 | `card` + `quiz=true` | 逐题展示→写答案→看参考答案 | `CardReminderActivity` |

- 仓库：`git@github.com:qiuyinlan/reminder_rest.git`（public，默认分支 `main`）
- 本地路径：`/root/.openclaw/workspace-bot4/reminder_rest`
- 技术栈：Java + Gradle（AGP 8.10.1 / Gradle 8.11.1 / compileSdk 35 / minSdk 26），纯代码构建 UI，无 XML 布局，数据存 SharedPreferences + JSON
- 底部导航 6 项：首页 / 任务 / 卡片 / 事项 / 陪伴 / 统计（`BottomNavigationBar` 常量顺序即页面 action 顺序）

## 2. 环境限制（重要）

1. **服务器没有 Android SDK**，不能本地编译。所有编译验证靠 GitHub Actions，push 后约 4-6 分钟出结果。
2. **服务器直连 github.com:443 被墙**：
   - git 操作走 SSH（22 端口，密钥已配好，可直接 push）
   - 下载 release 资产 / raw 文件用代理：`https://ghfast.top/https://github.com/...`
   - `api.github.com` 可用，查 CI 状态、release 用它
3. GitHub CLI 装了但没有 token（device flow 走不通），不要依赖 `gh auth`。
4. **App 内的更新检查也踩过这个墙**：`raw.githubusercontent.com` 国内常不可达，已改成多地址回退（raw → `ghfast.top` 镜像 → `jsDelivr`）。新增任何远程读取都要考虑这点。

## 3. CI / 发版规则

- **只有 `main` 和 `feature/**` 分支 push 会触发编译**（workflow `Android Build`）。`fix/**`、`smoke/**` 不会跑——改完想验证，就推到 feature 分支或直接进 main。
- 打 tag 自动发版：workflow `Release APK`
  - `v0.3.0` 形式 → 正式通道，更新 `update-manifest.json`
  - `v0.3.0-betaN` 形式（带横杠）→ 测试通道，更新 `beta-manifest.json`
  - 发布说明放在 `.release-notes/<版本>.md`，workflow 取第一行作为 manifest 的 notes
- **发版流程（顺序别错）**：
  1. 写代码 + 写 `.release-notes/0.3.0-betaN.md`，推 main，等 Android Build 绿
  2. `git fetch origin main && git rebase origin/main`（workflow 可能刚提交过 manifest）
  3. `git tag v0.3.0-betaN && git push origin v0.3.0-betaN`
  4. 等 Release APK 绿，`git pull` 把 manifest 提交拉回来
  5. 给用户直链：`https://github.com/qiuyinlan/reminder_rest/releases/download/v0.3.0-betaN/rest-bean.apk`
- 签名：
  - 测试通道用仓库内固定密钥 `ci/beta-signing/restbean-beta.jks`（密码见同目录 `credentials.properties`），保证 beta 之间可覆盖升级
  - **将来用户提供正式 keystore 后**：加 GitHub Secrets 四件套 `RELEASE_KEYSTORE_BASE64` / `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD`，workflow 已有读取逻辑且 secrets 优先
  - 注意：换签名的那一次，用户必须卸载重装
- versionCode：正式版从 `update-manifest.json` 自增，beta 从 `beta-manifest.json` 自增，别混用。`app/build.gradle` 里 `.orElse('0.1.7')` / `.orElse('8')` 只是兜底默认值。

## 4. 已完成功能（截至 beta24）

### 4.1 数据层

- `ReminderSettings.Rule` 字段：`module`、`deckId`、`quiz`、`daysMask`（每周位掩码，周一=1…周日=64）、`onceAt`（单次时间戳）、`title`、`enabled`
- 调度四种：每天固定点 / 每周指定星期 / 单次定时 / 时间段内每 N 分钟
- `ReminderRecord` 带 `module`，旧记录默认 body
- `Tasks`：`Tasks.today()` 只返回「今天该出现」的任务（单次任务 `onceAt` 晚于今日 23:59:59 则隐藏；每周任务只看星期）
- `Subtasks`：子任务复用 Rule 存，`module=subtask`、`deckId="p<父id>"`；完成写 `ReminderRecord(module=subtask)`

### 4.2 提醒链路（beta8 / beta12 / beta19，重点看）

- 所有模块的闹钟到点都**先尝试悬浮霸屏页**（`ReminderOverlayWindow` 是模块感知的：标题/文案/按钮/跳转目标各不同），拿不到悬浮窗权限才退回通知
- 所有提醒 `setFullScreenIntent(true)`，锁屏也能拉起；通知渠道 `health_breaks_v3`
- **保存规则后必须立刻调 `ReminderScheduler.update()`**。`ReminderSettings.upsertRule` 已经内联调用，别再绕过它直接写 prefs
- 诊断页：设置 → 提醒与权限 →「提醒诊断」（`ReminderDiagnosticsActivity`）：权限状态、每条规则的下一闹钟、最近触发记录、重排、测试霸屏页、测试通知

### 4.3 任务（beta14 / beta18 / beta20）

- 任务行 = 方格 checkbox + 任务名；勾完沉到底部「已完成 N 个 ⌄」折叠区；跨天自动回待办
- 未来任务收在底部「之后的任务 N 个」；任务编辑里「单次 + 日期」就是排到之后
- 长按菜单：编辑提醒设置 / 看子任务 / 删除 / 开关单独提醒（统一用 `FormKit.options`）
- FAB 新建：只填名字，默认每天 9:00、`enabled=false`（日常靠总览提醒）
- 总览提醒卡片：开关 + 起止时间 + 间隔（15/30/45/60/自定义），默认 09:00-21:00 每 30 分钟；支持跨夜时段

### 4.4 卡片（beta9 / beta14 / beta19 / beta21）

- 卡片集 JSON 导入（格式见 `docs/示例卡片集.json`），也支持手动新建；阅读 / 答题两种模式
- 提醒两种模式：固定时间点 / 每 N 分钟（顺序抽卡，进度 key `card_index_deck_<deckId>`，跨天接着上次）
- 霸屏页 `CardReminderActivity`：顶部卡片集名 + 「切换卡片集 ›」，中间卡片，`‹ 上一张 / 下一张 ›`，底部「学完了 / 关闭 / 关闭并稍后提醒」；稍后提醒用 `WheelPicker` 两列滚轮
- 卡片可勾「同时加进任务清单」（`CardDeck.Card.taskRuleId`），卡片集详情页可勾选

### 4.5 统计 / 崩溃兜底（beta3 / beta4 / beta6）

- `StatsActivity` 顶部按模块分流；`render()` 全包 try/catch，出错显示「统计页加载失败」+ 复制错误，不再闪退
- 根因教训：`records()` 方法体里 `for (ReminderRecord r : records())` 自递归 → StackOverflowError。改成了 `ReminderRecord.all(this)`
- `CrashLog`：全局 uncaught handler，同一份日志只提示一次，带日志版本号；设置 → 数据 可查看/复制/清空

### 4.6 性别 / 经期 / 身体数据导入导出（beta1 / beta10 / beta11）

- `UserProfile`：女 / 男 / 不指定；选女后首页出现「今天来了 / 今天结束」，统计页出现经期卡
- `PeriodLog`：`period_yyyy-MM-dd` → 结束日；日历画日期下方 7dp 粉线；未来日期不能开始，进行中时按钮变灰
- `BodyExportActivity` / `BodyImportActivity`：CSV（UTF-8 BOM），`日期,类型,详情`，支持合并导入 / 清空后导入
- ⚠️ 导入导出**只覆盖身体记录 + 经期**，不含任务 / 卡片 / 提醒设置

### 4.7 时间点可编辑（beta5）

- 事项页、卡片提醒的时间点行可点击，`WheelPicker.time` 预填原值，直接替换不用删了重加；卡片提醒支持秒级

### 4.8 全模块减字（beta22 / beta24，用户主动要求）

## 5. 踩过的坑（血泪版）

1. **只写配置不排闹钟**：`upsertRule` 不调 `ReminderScheduler.update()`，用户设完退出，规则永远显示「未安排」。已内联修复，别绕。
2. **`covered` 判断写死**：commit `50fd29e` 把卡片/任务改成 `!rule.isBodyModule() ? false : overlay`，从此只剩通知，用户以为「以前能霸屏后来不行」。排查思路：`git log -S` 找行为变更点，比猜权限快。
3. **每个 runner 全新机器**，debug 签名每次都不同 → APK 不能覆盖安装。已用固定测试密钥解决；`app/build.gradle` 已改成「有 keystore 才用 release 签名，否则回落 debug」。
4. **CI 失败看不到日志**（`actions/runs/{id}/logs` 要 admin token）。`Android Build` 失败会把日志推到 `ci-log` 分支，`git clone -b ci-log` 读。
5. **release workflow 会往 main 提交 manifest**：本地 main 落后时 `merge --ff-only` 会失败；tag 推错提交要删 tag 重推（beta15 踩过）。
6. **`fix/**` 不触发 CI**：以为在验证，其实压根没编译。
7. **自定义输入框白底白字**：裸 `EditText` 没设文字颜色，用户以为输入没生效。用 `FormKit.input`。
8. **原生 `setItems` 弹窗**被用户评价「特别丑」：一律 `FormKit.options`；原生 `dialog.show()` 一律 `FormKit.showStyled()`。
9. 本地不能编译时，**改完先自己核对括号/大括号平衡和变量作用域**，再推分支（beta4 / beta16 都因这类小错挂过 CI）。
